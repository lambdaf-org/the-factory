# Style

This file is a starting point. Adapt the language, register, and domain conventions to your own work, but the anti-slop principles below apply broadly.

Say plainly what is. Don't stage it, don't confirm it, don't contrast it against an alternative nobody raised. State the fact and move on. Drop the sentences that sound like someone narrating their own result: "this confirms the assumption", "this demonstrates that", "this shows that", "this underscores", "this highlights". If a thing is true, write it as true. The reader does not need you to point at your own work and approve of it.

Cut the "not X but Y" reflex. Constructions like "not a bug but a feature", "the key factor is design, not luck", and "it's not about speed, it's about correctness" feel insightful and almost never are. Say what it is. If a contrast genuinely matters, make it once, concretely, and don't dress it up as a reveal.

Start with the content. No throat-clearing openers ("it's worth noting", "it should be mentioned", "in this context"). No signposting about what you are about to do ("in the following", "we will now examine", "as outlined below"). Don't open a section with a sweeping statement about the field, and don't close it with a summary of what you just said. Begin with the actual point and stop when the point is made.

Keep the prose lean. No filler words, no rhetorical questions, no piling nouns onto nouns to sound formal. Drop empty emphasis: "crucial", "fundamental", "groundbreaking", "central", and their friends carry no information unless you back them with a reason, and usually you can just delete them. Limit yourself to at most one em-dash per paragraph.

Write short, clear, active sentences. One main idea per paragraph. Vary the length of sentences and paragraphs so the text has a rhythm; uniform blocks of identical-length lines read like a machine produced them.

Never use the "**Bold term:** explanation sentence" format. A bolded label followed by a colon and a definition is the single most recognizable AI tell. Write flowing prose instead, or a plain list when a list is genuinely the right shape.

Leave the substance alone. Don't touch technical terms, proper nouns, product names, or code examples. Improve the wording, never the argument.

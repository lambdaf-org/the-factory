# Time

Work is not linear. Things get rewritten, abandoned, resumed, contradicted by later decisions. A section that was correct two weeks ago may now conflict with code that changed since.

When reading context, watch timestamps, file modification dates, and version indicators. More recent material overrides older when the two conflict. If you can't tell which is newer, flag it rather than picking one.

Notes from prior runs may be stale. Verify claims in `notes/` against the actual files before relying on them. If something changed, update the note immediately.

When writing, don't assume the reader knows the chronological order of decisions. State what IS, not what WAS and then changed. The output should read as a coherent snapshot, not a changelog.
